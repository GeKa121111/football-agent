# Football Agent

لعبة محاكاة لإدارة وكالة لاعبي كرة القدم. تبدأ كوكيل صغير، تكتشف المواهب، تتعاقد مع اللاعبين، تفاوض الأندية، وتبني وكالة تنافس على مستوى العالم.

> حالة العمل: المراحل الأولى حتى الرابعة مكتملة على فرع المرحلة الحالية بعد اختبارات القبول. المرحلة التالية هي المرحلة الخامسة: التقويم والأحداث ودورة اللعب.

## الرؤية

- تجربة عربية RTL ومصممة للموبايل أولًا.
- بطاقات لاعبين مرسومة بأسلوب شبه واقعي، بهوية داكنة ولمسات بنفسجية.
- أنيميشن خفيف وسلس للشخصيات والبطاقات والأحداث.
- محاكاة مستقلة عن واجهة العرض: قرارات الوكلاء والأندية واللاعبين لا تعتمد على الشاشة.
- عالم كرة قدم يتطور عبر المواسم، مع انتقالات وعقود ومنافسين وأحداث.

## التقنية

- HTML5 + CSS3.
- JavaScript ES Modules بدون إطار واجهات ثقيل.
- Vite للتطوير والبناء.
- اختبارات Node.js المدمجة عبر `node:test`، واختبارات متصفح Playwright/Chromium.
- حفظ محلي بإصدار Schema واضح وقابل للترحيل مستقبلًا.

## التشغيل محليًا

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

## الاختبارات والبناء

```bash
npm run check
npm run build
```

5. التقويم والأحداث ودورة اللعب — المرحلة التالية.
6. الكشافون واكتشاف المواهب.

12. الذكاء الاصطناعي والعالم الحي.
13. الإعلام والإنجازات والتجربة القصصية.
14. الاختبارات النهائية والإطلاق 1.0.

## المرحلة الثالثة

تم إنشاء نظام رسوم SVG أصلي لشخصيات اللاعبين مع تنويعات للوجه والشعر واللحية والطقم، وحركة خفيفة تراعي إعداد تقليل الحركة. اجتازت المرحلة 14 اختبار وحدة و12 اختبار متصفح. راجع [سجل قبول المرحلة الثالثة](docs/PHASE-3-PLAYER-ART.md).

## المرحلة الرابعة

تم إنشاء قاعدة بيانات تأسيسية مترابطة تضم 8 دول و8 دوريات و10 مسابقات و16 ناديًا و16 ملف لاعب خياليًا. ترتبط الأندية بالدوريات والدول، واللاعبون بالأندية والجنسيات، وتُفحص العلاقات والمعرفات والقيم عبر اختبارات مستقلة. واجهتا اللاعبين والكشافين تقرآن الملفات من قاعدة العالم بدل بيانات العرض المنفصلة. راجع [سجل قبول المرحلة الرابعة](docs/PHASE-4-WORLD-DATABASE.md).

## حالة النسخة الحالية وحدودها

واجهة اللعبة تعرض خمس شاشات عربية وشبكة 18 قسمًا، مع بحث وفلاتر ونوافذ تفاصيل وحفظ قائمة متابعة. قاعدة العالم الحالية عينة تأسيسية فقط: أسماء الأندية والدوريات مرجعية، أما جميع ملفات اللاعبين فهي خيالية ولا تمثل قوائم رسمية. أعداد الأندية والمشاركين محدودة ولا يوجد تحديث مباشر من مزود بيانات. فرص الانتقالات المعروضة توضيحية، ولم تُفعّل بعد محاكاة فعلية للكشافين أو العقود أو التفاوض.

## مبادئ التطوير

1. كل كيان له ID ثابت، ولا نعتمد على الاسم كمفتاح.
2. محركات المحاكاة مستقلة عن واجهة المستخدم.
3. أي عملية مالية أو انتقال تمر عبر قواعد تحقق مركزية.
4. الحفظ له إصدار واختبارات، ولا نمسح ملفًا تالفًا تلقائيًا.
5. لا نضيف أنظمة ضخمة قبل اختبار دورة اللعب الأساسية.
6. الأداء على الموبايل معيار أساسي في كل مرحلة.
