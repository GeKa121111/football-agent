# Football Agent — المرحلة العاشرة: المنتخبات الوطنية والمباريات الدولية

**الحالة:** قيد التنفيذ على فرع مستقل.  
**الفرع:** `phase-10-national-teams`  
**نقطة البداية:** `059d384d390406fdd6305ad67bb699d170729c5f` — دمج المرحلة التاسعة في `main`.

## الهدف

إضافة طبقة كرة قدم دولية فوق عالم الأندية الحالي: منتخبات مرتبطة بجنسيات اللاعبين، قوائم استدعاء منطقية، فترات توقف دولي، مباريات وبطولات للمنتخبات، ثم إحصائيات وأرشيف. تظل الجنسية جزءًا ثابتًا من هوية اللاعب ولا تتغير عند انتقاله بين الأندية.

لا تعيد المرحلة بناء محرك المباريات أو محرك الموسم المحلي، ولا تنشئ قاعدة لاعبين ثانية. تستخدم بيانات العالم الحالية ومحرك المباراة بواجهات تكامل واضحة.

## 10.1 — هوية المنتخبات واختيار القائمة

**منفذ على الفرع الحالي:**

- [x] إنشاء دليل منتخبات تلقائي من الدول الموجودة في قاعدة العالم.
- [x] اختيار قائمة أساسية من 23 لاعبًا لكل منتخب بتوزيع مراكز: 3 حراس، 7 دفاع، 7 وسط، 6 هجوم.
- [x] حصر المرشحين في اللاعبين أصحاب الجنسية المطابقة؛ النادي الحالي لا يغيّر أهلية اللاعب الدولية.
- [x] ترتيب المرشحين اعتمادًا على تقييم التطور الحالي والإمكانيات واللياقة.
- [x] استبعاد المصابين وغير المتاحين، مع دعم قائمة استبعاد صريحة للاختبارات والاختيارات اللاحقة.
- [x] منع تكرار اللاعب أو إدخال لاعب محاكاة مجهول أو لاعب من جنسية أخرى.
- [x] إضافة اختبارات لكل المنتخبات، وتوزيع المراكز، والأهلية، والإصابة، والتقييم الديناميكي، وحالات نقص مركز مطلوب.
- [x] عدم تغيير مخطط الحفظ في هذه الشريحة؛ الاختيار حاليًا عملية مشتقة قابلة لإعادة الإنتاج.

## 10.2 — فترات التوقف والاستدعاءات

- [ ] تعريف نوافذ دولية داخل تقويم المسيرة، مع منع تكرار نفس الاستدعاء.
- [ ] تسجيل القائمة المستدعاة واللاعبين المنسحبين أو المصابين وتاريخ القرار.
- [ ] مراعاة ارتباط اللاعب بنادٍ وانتقاله الحالي دون تغيير جنسيته.
- [ ] عدم إيقاف مباريات الأندية عشوائيًا؛ تُعالج التعارضات من خلال قواعد جدولة صريحة.

## 10.3 — المباريات الدولية

- [ ] بناء تشكيل المنتخب من القائمة المسجلة مع حارس مرمى ومراكز صالحة.
- [ ] إعادة استخدام محرك المباراة الحتمي، مع معرف مباراة ونوع منافسة دولية مستقلين عن مباريات الأندية.
- [ ] تسجيل المشاركات والدقائق والأهداف والصناعة والتقييمات الدولية منفصلة عن إحصائيات النادي.
- [ ] منع احتساب نفس النتيجة أو الأداء مرتين، ودعم الإصابات والتعافي عبر دورة اليوم المشتركة.

## 10.4 — البطولات الدولية

- [ ] إضافة بطولات قارية للمنتخبات وفق الاتحادات الموجودة في قاعدة العالم.
- [ ] دعم مجموعات وترتيب وفواصل تعادل وتأهل وخروج مغلوب ونهائي.
- [ ] إنشاء بطولة عالمية للمنتخبات من الدول المؤهلة في قاعدة المحاكاة، مع قواعد أهلية معلنة بدل التأهل العشوائي.
- [ ] أرشفة البطل والنتائج والجوائز الفردية عند اكتمال البطولة فقط.

## 10.5 — الربط بتجربة الوكالة

- [ ] إظهار استدعاءات عملاء الوكالة ومواعيد المعسكرات والمباريات في التقويم والوارد.
- [ ] إظهار سجل اللاعب الدولي في ملفه وتقارير الكشافين دون خلطه بأداء النادي.
- [ ] ربط السمعة والاهتمام الإعلامي بالإنجاز الدولي وفق عوامل محدودة وشفافة.
- [ ] عدم منح انتقال أو عقد أو مكافأة مالية تلقائيًا بسبب الاستدعاء.

## 10.6 — الحفظ والأرشيف والاعتماد

- [ ] إضافة بنية حفظ دولية اختيارية مع ترحيل متوافق إذا لزم.
- [ ] اختبار الاستدعاء والمباريات والبطولات عبر أكثر من موسم.
- [ ] اختبار الحفظ وإعادة التحميل وعدم فقد النتائج أو تكرار المباريات أو الجوائز.
- [ ] فحص CI وPlaywright والبناء، ثم الدمج والنشر بعد نجاح بوابة الاختبارات.

## ضوابط التصميم

1. `player.countryId` هو مصدر الجنسية الوحيد في المرحلة الحالية؛ لا نستنتج الجنسية من النادي أو الدوري.
2. القائمة الدولية تتكون من لاعبين معروفين في قاعدة العالم فقط، ولا تقبل لاعبي `simulationOnly`.
3. تقييم اللاعب في قائمة المنتخب يأتي من سجل التطور الحالي إن وجد، وإلا من تقييم قاعدة العالم.
4. لا تُحفظ قائمة المنتخب المشتقة بوصفها نسخة ثانية من اللاعبين؛ تُحفظ لاحقًا الاستدعاءات والقرارات والنتائج فقط.
5. لا يُغيّر مخطط الحفظ أو سلوك مباريات الأندية قبل توفير اختبارات توافق مستقلة.
6. بيانات اللاعبين والأندية والمنتخبات خيالية للمحاكاة وليست قوائم رسمية حية.

## حالة التحقق الحالية

- اختبارات الوحدة الجديدة: 7 سيناريوهات تغطي دليل المنتخبات، القوائم الـ23، الجنسية، التقييم واللياقة، الإصابات والاستبعاد، رفض البيانات غير السليمة، ونقص المراكز.
- لم يُعلن اعتماد المرحلة بعد؛ يلزم تشغيل CI على الفرع ومراجعة تكامل المحرك مع تقويم المسيرة قبل الانتقال إلى 10.2.
