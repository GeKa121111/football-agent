# ضوابط المستودع وحماية الفرع الرئيسي

## بوابة النشر

يعيد Workflow النشر تشغيل اختبارات الوحدة واختبارات Chromium لسطح المكتب والموبايل وفحص الصياغة وبناء الإنتاج. لا يرفع Artifact إلى Pages إلا بعد نجاح جميع الخطوات.

## حماية فرع main — إعداد يدوي مطلوب

آخر فحص لإعدادات المستودع أظهر أن حماية فرع `main` غير مفعّلة. واجهة GitHub المتاحة لهذه الجلسة تسمح بقراءة إعداد الحماية لكنها لا توفر عملية كتابتها؛ لذلك لم يتم الادعاء بتفعيلها.

لتفعيل الحماية من إعدادات GitHub:

1. افتح Settings → Branches → Add branch ruleset (أو Branch protection rule).
2. استهدف الفرع `main`.
3. اشترط إنشاء Pull Request قبل الدمج، وامنع force pushes وحذف الفرع.
4. اشترط نجاح فحص الحالة `Validate Football Agent / validate` قبل الدمج، مع تفعيل تحديث الفرع قبل الدمج عند الحاجة.
5. لا تشترط موافقة مراجِع إضافية إلا إذا كان هناك شخص آخر سيقوم بالمراجعة؛ لا نريد قاعدة تمنع صاحب المشروع من الدمج منفردًا.

الرابط المباشر: https://github.com/GeKa121111/football-agent/settings/branches

## معايير الحفظ

- أرقام اليوم والأسبوع يجب أن تتفق وفق `week = ceil(day / 7)`.
- معرفات العملاء في الوكالة ومعرفات سجلات اللاعبين والأندية والمسابقات والعروض يجب أن تكون نصوصًا غير فارغة وفريدة داخل مجموعاتها.
- لا يؤدي فشل التحقق إلى حذف الحفظ أو تصحيحه تلقائيًا؛ تظل البيانات الأصلية كما هي.
- تبقى بنية الحفظ على الإصدار 2؛ لم تتم إضافة ترحيل أو إعادة كتابة لبيانات المستخدم.

## توافق حفظ المهام القديمة

قد تحتوي بعض ملفات الحفظ القديمة من الإصدار 2 على مهام مكتملة أقدم من حقل `completedLate`. يستمر التحقق في قبول غياب هذا الحقل للحفاظ على التوافق، لكنه يرفض القيم الصريحة المتعارضة مع تواريخ التسليم والإنجاز.
